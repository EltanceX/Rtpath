# RtPath 阶段 2 搜索验证与性能

## 搜索和分页

| 写法 | 示例与匹配方式 |
| --- | --- |
| 名称子串 | `项目索引`，按经 Unicode NFC 和大小写折叠后的文件名匹配。标点按字面处理。 |
| 完整名称或前缀 | `name:"Main Activity.kt"` 或 `prefix:Main`。一次查询使用一种名称匹配方式。 |
| 扩展名 | `ext:kt` 或 `ext:.kt`，匹配折叠后的最后一段扩展名。 |
| 目录 | `path:"src/Feature A"` 或索引可见的绝对路径。只匹配目录内的条目，边界按路径段判断。 |
| 大小 | `size:>=1MiB size:<3MB`，十进制单位和二进制单位分别换算。只返回大小已知且满足条件的条目。 |

可以组合名称、扩展名、目录和大小条件。按名称、路径、大小、修改时间升降序时，以条目 ID 打破并列。每页最多 100 条，游标绑定范围、查询、排序、发布版本及修订号。Flutter 滚动时追加结果，空候选批次会继续搜索，收到过期游标时从第一页重查。窄屏行显示文件元数据，宽屏使用可点击排序的列标题。两种布局均可复制完整路径。

已有阶段 1 索引在首次使用时事务迁移，保留已发布范围和索引版本。索引新增名称、路径、大小、修改时间和扩展名的 B-tree，以及维护名称键的 FTS5 trigram。相对路径排序键依据原始父目录关系构建。后续接入目录移动时，需要在同一已发布修订里保持排序键、路径过滤与父目录关系一致。

## 验收范围

- Android 16 真机通过普通及共享范围回归、中文一字和二字、同名正反向分页、组合过滤、标点和 Unicode 归一化。完整重扫使旧游标失效，滚动能加载下一页且搜索框保持可用。
- Flutter 界面测试覆盖窄屏、宽屏、大小及时间显示和复制路径动作。Profile 基准验证旧库原位迁移、模拟关闭 trigram 时的候选回退，以及每条记录的分页对账。
- 2026-11-23 在 Xiaomi sheng 验证，环境为 Android 16 / API 36、arm64-v8a、Linux 5.15.178 和 SQLite 3.50.1。测试包通过 `su` 安装，测试及 SQL 运行在应用 UID 下。

## 性能口径

基准在同机 Profile 测试包中写入 10 万和 100 万条合成元数据，每种规模含 100 个目录，文件名涵盖重复扩展名、中英文、字面引号和标点，高频与低频名称，以及实际走筛选的大量不同大小与时间。临时库在测试结束后删除。内存对照从相同 SQLite 库载入各字段，预排序四个顺序，使用同一过滤契约和 100 条页大小。两侧每类查询预热 5 次、计时 100 次。SQLite 计时包括打开连接、读事务、选择计划和构造结果对象。内存载入和预排序单独计时。短词尾部命中累加各批次耗时，按一次完整查询报告。

三字符及以上的低命中子串从 FTS5 点查行元数据，再对命中项排序。高命中或一二字符的子串顺着排序索引按批检查，每批最多 2,048 个候选。组合查询中的小子树先用路径索引筛选。大小分页用有索引的大小键加条目 ID 定位下一页。初测百万条组合筛选的 P95 为 398.06 ms，初始短词批次约 170 ms。查询计划显示前者遍历大量 FTS 命中再筛选，后者通过版本及 ID 索引取条目后做临时排序。

这是应用内数据库查询基线，系统缓存已预热，建库计时使用合成批次。Flutter 输入防抖、Pigeon 往返、首帧绘制、全盘实际遍历和增量刷新时延需单独测量。Android 10 及 x86_64 运行仍需对应设备验收。

## 复现

在 Windows 完成首次 Android 构建并配置终端后运行。[项目 README](../README.md)

```powershell
./tools/verify-ordinary-scan.ps1 -Serial '<device-id>' -Shared
./tools/verify-search-performance.ps1 -Serial '<device-id>'
```

第二个脚本在 `.local/artifacts/phase2-performance.txt` 写入原始统计与 `EXPLAIN QUERY PLAN`。

双 ABI 日常 Debug APK 保存在 `.local/artifacts/rtpath-stage2-debug.apk`，SHA-256 为 `f21bcd7f4fad0028395b208d16b54cf73170518d11870ea404a409ab425bf25e`。
