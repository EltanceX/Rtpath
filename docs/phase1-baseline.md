# RtPath 阶段 1 验证记录

2026-11-23 在 Xiaomi sheng 上完成普通扫描和索引闭环验收。设备运行 Android 16（API 36）、arm64-v8a 和 Linux 5.15.178，应用使用打包的 SQLite 3.50.1。Debug APK 通过 KernelSU 授权的 ADB Shell 安装，扫描、授权检查和查询均在 Android 分配给应用的普通 UID 下执行。

## 实现

1. 用户从应用内部目录、应用外部专属目录或已授权共享卷选择扫描入口，可填写入口下的相对目录。Android 11+ 使用系统的「所有文件访问」授权，Android 10 使用旧版存储授权。
2. C++ 通过目录 FD 遍历，记录文件和目录的父 ID、原始名称字节、类型、大小及修改时间。符号链接作为条目记录，遍历跳过其他挂载。Android 11+ 优先用 `statx` 取挂载 ID，旧系统或缺少该字段时用 `/proc/self/fdinfo`。
3. JNI 每 512 条发送一个批次，Kotlin 用单写线程写入应用私有的 SQLite WAL 索引。事务切换某个范围的当前版本。取消、失败和有读取缺口的重扫保留该范围已有版本，首次部分扫描可发布并标记部分覆盖。进程下次启动索引服务时清理未发布的数据。
4. Pigeon 接通扫描、取消、状态与查询。查询在同一读事务内绑定发布版本，对文件名做 Unicode 正规化、大小写折叠和字面子串匹配，从父目录关系拼出路径。共享存储授权撤销后，该范围从索引列表移除且无法查询。

## 验收

| 检查 | 真机结果 |
| --- | --- |
| Flutter 静态检查与界面测试 | `flutter analyze`、`flutter test` 通过。真机从搜索页发起重扫并返回匹配结果。阶段 0 文件读取、inotify 和 SQLite trigram 探针通过回归。 |
| 应用内部目录 | 嵌套文件的路径与字节数正确，中文、大小写和字面 `_%` 匹配通过。指向扫描根的符号链接以链接类型返回，扫描完成。 |
| 共享存储 | 在获授权的主共享卷 `Download` 子目录完成建索引和查询。撤销测试包授权后，列表和直接查询均隐藏该索引。 |
| 重扫与取消 | 以 24,000 个额外文件制造重扫窗口。暂存批次已开始落盘时可查询旧版本，取消后旧版本及其结果仍可读。 |
| 发布与失败 | 完整重扫切换到新版本，查询返回替换后的结果。触发深度上限时，新范围标为部分，已有范围保留上次索引。缺失根目录报告失败。 |
| 重启 | 强制停止测试包，再启动并读到同一已发布版本和文件名，无需重新扫描。 |
| 构建 | Debug APK 的 `arm64-v8a` 和 `x86_64` 均含 Flutter、RtPath 与 SQLite 原生库。日常版经 `su` 安装后在 arm64 真机启动。 |

测试夹具由隔离应用 `io.github.eltancex.rtpath.testhost` 创建，覆盖内部路径和共享存储的临时目录。完成首次 Android 构建后，按 README 配置终端并运行以下脚本。[项目 README](../README.md)

```powershell
./tools/verify-ordinary-scan.ps1 -Serial '<device-id>' -Shared
```

本次日常版 APK 保存在 `.local/artifacts/rtpath-stage1-debug.apk`，SHA-256 为 `9d73413a220e30d394285e7a4a03f8e44c717f7e69334f4cab8985476291e199`。

## 当前范围

- 每次搜索最多返回前 100 条，使用普通 SQLite 表匹配。分页、排序、筛选以及 10 万和 100 万条的性能对照在阶段 2 进行。
- 单次扫描上限为 200 万条和 512 层打开的目录，触及上限会报告部分覆盖。非法 UTF-8 的名称保留原始字节，界面路径使用带替换字符的显示文本。
- Android 10、x86_64 运行、可移动卷和扫描进行中强制结束进程的故障注入仍待设备矩阵验证。Root 扫描和文件事件驱动更新按后续阶段接入。
